# 超长文档审写

ReviewWrite 对十万字及更长的 UTF-8 文本使用分块预检和全局一致性索引，不把全文粗暴塞进一次模型上下文，也不把每个片段当成互不相关的短文。

## 适用范围

适用于 Markdown、纯文本以及已经抽取为 UTF-8 的长篇正文。DOCX/PPTX 的字体和版式仍由 Office QA 处理；如需长文正文审写，应先使用宿主或用户确认的方式抽取正文，并保留章节、段落和页码映射。

默认入口：

```bash
python3 scripts/long_document_review.py path/to/long-draft.md --format json
```

默认每块最多约 12,000 个字符，并保留有限上下文重叠。切分优先落在 Markdown 章节标题之前，其次使用段落或行边界，减少把标题与正文拆开的情况。可以按模型上下文和机器资源调整：

```bash
python3 scripts/long_document_review.py path/to/long-draft.md \
  --max-chars 12000 --overlap 256 --genre research-report --format json
```

## 四层能力

1. **分块预检**：每块独立执行现有泄漏、模板和风格信号规则，并将结果映射回全文行号和块号；
2. **全局索引**：一次建立全文行偏移索引，再汇总标题、中文语境中的年份、百分比、数量、金额及其位置；避免为每个数字和标题从文首重复计算行号；
3. **一致性线索**：发现英文术语大小写/拼写变体和重复段落，提示人工或模型统一核对；
4. **边界可追溯**：保留字符数、行数、块数、重叠长度、失败/警告数量和限制说明；对发现项、标题、索引和重复组设置输出上限并报告省略数量，避免几十万字输入生成失控的结果文件。

## 长文档工作流

1. 先抽取并确认正文范围、章节结构、来源和保护项；
2. 运行长文档预检，先处理 blocker，再按章节汇总 major/minor 问题；
3. 对数字、术语、主张—证据关系和限定条件建立全局核对表；
4. 按章节改写，禁止把某一块新增的事实、例子或语气无依据地传播到其他块；
5. 修改后重新运行全篇预检，并对目录、摘要、结论、参考文献和关键附录做抽样人工复核。

## 不夸大的边界

分块预检解决的是上下文长度、定位和一致性线索问题，不等于自动完成十万字的事实核验或语义审稿。块之间的因果关系、跨章论证、引用真实性、法律责任和学术结论仍需全局模型/人工复核。数字索引、术语变体和重复段落只是线索，不自动判定错误。
