# 竞品与研究成果评估规范

目标是识别可验证的能力差距并形成原创改进，不是复制竞品文案、规则表或实现。

## 可接受来源

按可信度优先：

1. 竞品官方文档、公开 Skill、公开仓库和正式发布说明；
2. 有完整方法和限制说明的论文、预印本、基准或数据集；
3. 可复现的公开 issue、失败案例和评测；
4. 其他公开介绍，仅用于发现线索，不能单独支持代码修改。

每条来源必须记录 URL、访问日期、作者或机构、许可证或使用边界、可复现内容和限制。未知许可证代码不得复制；私人文本不得进入长期样例库。

## 每轮最多评估三个候选

对每个候选记录：

- 它解决的具体问题；
- 可观察的输入与输出行为；
- 支撑该行为的第一手证据；
- ReviewWrite 当前是否真的失败；
- 可转化为哪一个原创测试；
- 预期改善的指标；
- 可能伤害的体裁或边界。

没有“当前失败样例”的竞品能力只进入观察清单，不进入实现。

## “超越”门禁

只有同时满足以下条件，才能写入“已超过当前参考实现”：

1. 使用同一公开或合成测试条件；
2. 至少一个指标严格改善；
3. 事实、数字、引用、限定条件和体裁例外没有退化；
4. 实现和措辞为原创，不复制未知许可内容；
5. 报告同时列出仍然落后的维度。

可比较指标包括：误报、漏报、事实保持、引用保持、限定条件保持、跨体裁稳定性、中文自然度的专业评审结果、Office QA 可解释性、安装与回滚可靠性。禁止用 star、营销口号或单一“AI 分数”证明超越。

## 研究成果进入代码的条件

论文或基准只能提供假设和评测设计。进入代码前必须：

- 定义与 ReviewWrite 当前问题的对应关系；
- 构造本地最小失败样例；
- 验证许可和数据使用边界；
- 增加正例、反例和相邻体裁回归；
- 在变更日志中区分“来源结论”和“本项目推断”。
